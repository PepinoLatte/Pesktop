# Fences 类桌面管理软件 — 技术实现分析

> 对话时间：2026-06-17
> 技术栈：Rust + Tauri + Vue（Windows 平台）

---

## 一、目标

开发一款类似 Stardock Fences 的桌面图标管理软件，核心功能：

1. 把桌面图标"移进"半透明 Box（容器）中
2. Box 内的图标右键弹出**原生 Windows 右键菜单**

---

## 二、Fences 的工作原理

**一句话：Fences 贴了层"透明膜"盖住桌面，然后自己在膜上重新画图标。**

| 步骤 | 原理 |
|------|------|
| ① 找到桌面图标控件 | Windows 桌面实际是 Explorer.exe 里的一个 `SysListView32` 控件，所有图标是它的"列表项" |
| ② 藏起原始图标 | 子类化（Subclass）这个控件，拦截它的绘制消息，让原始图标**看不见** |
| ③ 自己重新画 | 开一个全屏透明窗口盖在桌面上，用 `DrawIconEx` 把所有图标再画一遍 |
| ④ "移进 Box" | 文件**物理位置不动**，只是把该图标的渲染位置从"桌面背景"改为"Box 内部" |
| ⑤ 原生右键菜单 | 调用 Windows 的 `IContextMenu` COM 接口，弹出来的菜单和 Explorer 右键完全一样 |

**本质：Fences 不是"操作桌面图标"，而是"接管了桌面的渲染层"。**

---

## 三、技术栈可行性分析

| 功能 | 能否用 Tauri+Vue 实现 | 原因 |
|------|----------------------|------|
| 桌面透明覆盖层 + 画图标 | ❌ | Webview 不适合做原生渲染 |
| 子类化桌面 ListView | ❌ | Tauri 进程不能直接 hook Explorer |
| 原生右键菜单 | ❌ | 需要 COM，不在 Webview 范畴 |
| 设置界面 / Box 布局编辑 | ✅ | Vue 做这个很合适 |

## 四、推荐架构：双进程方案

```
┌─────────────────────────────────────┐
│ Rust Win32 Helper（小 EXE）          │
│ - 透明全屏窗口覆盖桌面                │
│ - 画图标、接鼠标拖拽                  │
│ - 弹原生右键菜单                      │
│                                     │
│   CreateWindow(WS_EX_LAYERED|       │
│     WS_EX_TRANSPARENT|TOPMOST)       │
│   SetWindowSubclass(SysListView32)   │
│   IShellFolder + IExtractIcon        │
│   IContextMenu::QueryContextMenu      │
│                                     │
│              │                       │
│     Named Pipe / Local Socket        │
│              │                       │
│              ▼                       │
│                                     │
│ Tauri + Vue（主程序）                │
│ - Box 布局编辑器                      │
│ - 设置页面                           │
│ - 配置持久化                          │
│ - 与 Helper 通信传映射数据            │
└─────────────────────────────────────┘
```

**分工：**
- **Rust Helper** — 干脏活：覆盖桌面、画图标、接拖拽、右键菜单（纯 Win32 API）
- **Tauri + Vue** — 干界面活：设置、布局编辑、配置管理

> 和 Fences 的唯一区别：Fences 是单个 C++ EXE，你拆成两个进程。用户看到的效果一样。

## 五、关键技术要点

### 5.1 桌面窗口层级

```
Progman (FindWindow "Progman")
  └── SHELLDLL_DefView
        └── SysListView32 (桌面图标所在位置)
```

### 5.2 Rust 需要的核心 Crate

- `windows-rs` — Win32 API 和 COM 接口绑定
  - `UI::Shell` → `IShellFolder`, `IContextMenu`, `IExtractIcon`
  - `UI::WindowsAndMessaging` → `SetWindowSubclass`, `FindWindow`
  - `UI::Controls` → `LVM_GETITEMPOSITION` 等

### 5.3 IPC 通信选型

| 方式 | 复杂度 | 推荐度 |
|------|--------|--------|
| Named Pipe (windows-rs) | 中等 | ⭐⭐⭐ 首选 |
| Local TCP Socket | 低 | ⭐⭐ 简单但不够原生 |
| 共享内存 + Event | 高 | ⭐ 不推荐 |
