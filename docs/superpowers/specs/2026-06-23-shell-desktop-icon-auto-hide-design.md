# Windows 系统桌面图标收纳后自动隐藏设计

## 背景

Dasktop 现在已经支持把 Windows 系统桌面图标收纳到 Box，包括此电脑、回收站、网络、控制面板和用户文件夹。这些项目不是普通桌面文件，而是 Windows Shell 虚拟项，前端以 `shell::${shellId}` 作为稳定路径键，数据库以 `box_virtual_items.shell_id` 保存引用。

当前收纳行为只是在 Box 内保存一个虚拟项入口，Windows 原生桌面上的同一图标仍然可见。用户希望拖入 Box 后，原生桌面上的同一系统图标自动隐藏；从 Box 移除后，如果没有其他 Box 继续收纳它，再恢复显示。Dasktop 退出后保持隐藏，下一次启动继续由 Box 承接这些入口。

## 目标

- 设置页提供一个总开关：收纳系统桌面图标后隐藏原生图标。
- 开关开启时，系统图标被拖入任意 Box 后，隐藏 Windows 原生桌面上的对应图标。
- 同一个系统图标可以存在于多个 Box；只有所有 Box 都不再引用该图标后，才恢复原生桌面图标。
- Dasktop 退出后不恢复这些图标，保持桌面清爽；下次启动按数据库中的 Box 引用继续同步隐藏状态。
- 只恢复 Dasktop 自动隐藏过的图标，避免误改用户原本隐藏的 Windows 设置。

## 非目标

- 不处理普通桌面文件、文件夹、快捷方式的隐藏或移动。
- 不在退出 Dasktop 时临时恢复系统图标。
- 不为每个系统图标单独提供手动显示开关；第一版只做总开关和自动同步。
- 不迁移旧数据结构，当前项目未上线，新增字段按默认值直接生效。

## 推荐方案

采用“全局自动隐藏 + 智能恢复 + 设置总开关”的方案。

设置项命名建议为 `autoHideNativeShellIcons`，默认值建议为 `true`。默认开启能让“拖入 Box 等于收纳走原生图标”的体验更完整，也与用户确认的产品方向一致。如果用户不希望 Dasktop 修改 Windows 桌面系统图标设置，可以在设置页关闭该开关。

## 数据模型

### 应用设置

在 `AppSettings` 中新增布尔字段：

- `autoHideNativeShellIcons`: 是否在系统桌面图标被收纳进 Box 后自动隐藏原生图标。

### 自动隐藏记录

新增一张本地表记录 Dasktop 接管过的系统图标：

- `shell_id`: 系统虚拟项稳定 ID。
- `previous_visible`: Dasktop 首次接管前该图标在 Windows 桌面上是否可见。
- `managed_hidden`: 当前是否由 Dasktop 管理为隐藏。
- `updated_at`: 更新时间。

这张表用于区分“用户本来就隐藏了该图标”和“Dasktop 因收纳而隐藏了该图标”。恢复时只有 `previous_visible = true` 且当前已无 Box 引用的项目才会显示回桌面。

## Windows 能力边界

Windows 对这些系统桌面图标的显示状态通常存放在当前用户 Explorer 设置中，每个 CLSID 对应一个隐藏配置。实现层需要新增 Windows 基础设施模块，按 `shell_id` 映射到对应 CLSID，并提供这些能力：

- 读取某个系统桌面图标当前是否显示。
- 设置某个系统桌面图标显示或隐藏。
- 通知 Explorer 刷新桌面，使变更即时可见。

支持范围与当前 `shell_virtual_item` 保持一致：

- `this-pc`
- `recycle-bin`
- `network`
- `control-panel`
- `user-folder`

如果某个 Windows 版本不支持其中某个 CLSID 的显示状态写入，后端应返回可展示错误，前端只提示失败，不删除 Box 内引用。

## 同步流程

### 拖入 Box

1. 原生拖放层解析出 `shell_id`。
2. 前端把 `shell_id` 保存到当前 Box 的虚拟项表。
3. 如果 `autoHideNativeShellIcons = true`，调用同步逻辑。
4. 同步逻辑读取所有 Box 的虚拟项引用，发现该 `shell_id` 至少被一个 Box 引用。
5. 如果本地自动隐藏记录不存在，先读取 Windows 当前显示状态并保存为 `previous_visible`。
6. 将对应 Windows 原生桌面图标设为隐藏，并记录 `managed_hidden = true`。

### 从 Box 移除

1. 删除当前 Box 中的 `shell_id` 引用。
2. 同步逻辑重新统计所有 Box 引用。
3. 如果该 `shell_id` 仍被其他 Box 引用，保持原生图标隐藏。
4. 如果该 `shell_id` 已无任何 Box 引用，且本地记录表明 `previous_visible = true`，恢复 Windows 原生桌面图标显示。
5. 恢复完成后删除或清空该 `shell_id` 的自动隐藏记录。

### 启动同步

Dasktop 启动并完成数据库初始化后，应执行一次同步：

- 对仍被 Box 引用的系统图标，确保原生桌面图标处于隐藏状态。
- 对已经没有 Box 引用但仍存在管理记录的系统图标，按恢复规则处理。

这样可以覆盖应用异常退出、手动改数据库、或者上次运行中断导致的状态不一致。

### 开关关闭

用户关闭 `autoHideNativeShellIcons` 时，应立即执行一次恢复：

- 遍历 Dasktop 管理过的隐藏记录。
- 对 `previous_visible = true` 的图标恢复显示。
- 对 `previous_visible = false` 的图标保持隐藏。
- 清理 Dasktop 自动隐藏记录。

关闭后，拖入 Box 只保存引用，不再修改 Windows 原生桌面图标显示状态。

## UI 设计

设置入口放在“文件”或“窗口/桌面行为”相关面板中，文案建议：

- 标题：收纳系统桌面图标后隐藏原生图标
- 说明：此电脑、回收站、网络等系统图标进入 Box 后，将从 Windows 桌面隐藏；从所有 Box 移除后再恢复。

交互为普通开关。第一版不提供每个图标的独立开关，避免用户在“自动状态”和“手动状态”之间混淆。

## 错误处理

- Windows 设置写入失败时，保留 Box 内虚拟项引用，并在当前 Box 或设置页错误区域提示。
- Explorer 刷新失败时，不回滚数据库引用，因为 Windows 设置可能已经写入成功；下次启动同步会再次尝试刷新。
- 如果用户在 Windows 个性化设置中手动修改图标显示状态，Dasktop 下次同步以 Box 引用和本地管理记录为准；被 Box 接管的图标会重新隐藏。

## 测试策略

- 单个 Box 拖入“此电脑”后，原生桌面“此电脑”隐藏，Box 内入口可打开。
- 两个 Box 都引用“此电脑”时，从其中一个 Box 删除后原生图标仍隐藏。
- 从最后一个 Box 删除“此电脑”后，原生图标恢复。
- 用户原本隐藏“网络”时，拖入再移除后仍保持隐藏。
- Dasktop 退出后，被接管的系统图标仍隐藏；重新启动后 Box 内入口仍可用。
- 关闭总开关后，Dasktop 自动隐藏过的可见图标恢复，后续拖入不再隐藏原生图标。
